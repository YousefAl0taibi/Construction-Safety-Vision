# Results

The committed results were generated by `notebooks/train_colab.ipynb` on the held-out test split:

| Metric | Value |
|---|---:|
| Precision | 0.6584 |
| Recall | 0.5312 |
| mAP@0.5 | 0.5572 |
| mAP@0.5:0.95 | 0.2787 |

- `metrics.json` is the machine-readable summary.
- `confusion_matrix.png` shows class-level matches, false positives in the background column, and
  missed ground-truth objects in the background row.
- Model files are kept out of normal Git history and packaged for distribution through a GitHub
  Release.

## Error analysis

The raw counts in the committed confusion matrix separate the test-set errors into three groups:

| Error type | Count |
|---|---:|
| Ground-truth objects predicted as background (omissions) | 351 |
| Predictions with no matched ground-truth object (background false positives) | 225 |
| Confusions between two foreground classes | 8 |

Omissions are therefore the largest recorded error group. `Person` accounts for 38 missed
ground-truth objects. The weakest class-level result is `no_boots`: it has 0 correct matches and all
23 of its ground-truth instances were assigned to background.

These counts identify *where* the detector fails, but not *why*. In particular, the matrix does not
prove that object size caused the omissions. Establishing a small-object effect would require
stratifying the test results by bounding-box area (and separately checking factors such as lighting
and occlusion).

## Runtime benchmark

`benchmark.json` records a reproducible CPU measurement on the included synthetic demonstration
image. It separates model-only inference (`4.24 FPS`) from the complete in-memory image pipeline
(`3.79 FPS`). The latter includes annotation but excludes disk I/O and video encoding, so it should
not be presented as camera or production throughput. Hardware, versions, image size, warm-up count,
and measured iterations are stored with the result.
